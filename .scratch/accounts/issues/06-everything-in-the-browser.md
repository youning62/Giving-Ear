# 06: 所有操作都在网页里完成

**What to build:** 用户只需要启动一次服务（命令 `givingear`，或双击 `GivingEar.command`），之后所有操作都在浏览器里：设置 Gemini API 密钥、注册/登录账号、开始/停止监听、给房间里的人登记声纹、管理已登记的人。会话由服务进程管理（`app.py` 的 `Controller`），不再依赖命令行参数。命令行方式（`givingear run ...`、`account`、`speakers`）继续保留。

## 完成记录
- `src/givingear/app.py`：`Controller`（开始/停止/再开始、会话自己结束后回到空闲、停止时释放麦克风、网页上给某人登记声纹）和 `run_app`。音频源与后端用工厂函数创建，测试里换成 WAV 和假后端。
- 网页接口新增：`GET /api/state`、`POST/DELETE /api/settings/key`、`POST /api/session/start|stop|register`。事件流对晚到的网页先回放当前会话已发生的事件。
- API 密钥写入 `~/.config/givingear/env`（权限 600，沿用原有配置文件），接口只返回"已设置"和末 4 位。
- 入口：`givingear`（不带参数）启动网页服务并打开浏览器；`givingear run ...`（或只带选项）仍是命令行方式；双击 `GivingEar.command` 也能启动。
- 网页：顶部"开始/停止监听"，"设置"（密钥、回声消除开关），首次使用的引导提示条，卡片上的"登记声纹"，错误显示在页面提示条里。
- 已用无头 Chrome 对"会话进行中才打开页面"做过端到端检查（假 AI + 合成语音）。
- **没验证：** 真实麦克风权限弹窗（macOS 会把权限算在启动服务的终端 App 上）、真 Gemini 的对话、网页里点"登记声纹"的完整流程（接口有测试，按钮没点过）。
