# 有情感的朗读

**Status:** v1 完成（2026-11-05），待用真实的通义千问密钥或 CosyVoice 服务试听

## 背景

用户实测接入 DeepSeek 的版本，AI 的声音"完全没有情感"。原因有两层：
1. 现在的语音合成是 macOS 自带的 `say`，没有任何情感控制；
2. 文字模型只吐出纯文字，没有人告诉语音合成"这句话该用什么语气"。换成再好的情感语音模型，如果不解决第 2 点，也不会有情感。

## 设计

- **让文字模型给每句话标情绪。** 系统提示要求每句话开头写一个固定词表里的情绪标签（`[开心]` `[温柔]` `[难过]`……）。后端把标签从文字里剥掉（页面上和朗读都不出现），把情绪传给语音合成。
- **语音合成增加情绪参数**：`synth(text, emotion)`。情绪词表映射成自然语言的语气指令（"用开心愉快的语气，语速稍快"）。
- **三种语音引擎，设置里选择：**
  - 本机自带（macOS `say`）：离线、免费，没有情感，保持原样；
  - 通义千问云端（DashScope，`qwen3-tts-instruct-flash`）：国内直连，自然语言指令控制语气；需要 DashScope 密钥；
  - 本地 CosyVoice：用户自己部署 CosyVoice 的 FastAPI 服务（Apache-2.0），我们通过 HTTP 调用；免费，声音不出本机。
- 设置页提供"试听"：选一个情绪，当场听效果。
- 提示里鼓励适当用语气词（"嗯""哈哈"），让话更像真人。

## 借鉴与许可

- Qwen TTS 的调用方式（接口地址、`instructions` 字段、返回音频地址）来自 QianWen-AI/qianwen-ai 的 qianwen-audio-tts skill（Apache-2.0）；CosyVoice 服务的接口来自其 FastAPI 示例（Apache-2.0）。
- noizai/skills 的 characteristic-voice 没有许可证，不拷代码，只借"语气词"这个通用想法。
- 评估过但没有采用：IndexTTS2（bilibili 自定义许可：月活 1 亿或年收入 10 亿以上要另行授权，且不能用输出改进别的商业模型）、Fish Speech（社区许可：托管服务需要另签商业授权，我们做网站平台很可能踩线）、ChatTTS（AGPL-3.0，会传染）。

## 已确认的决策（用户，2026-11-05）

- 软件以后要在手机上登录使用，所以**语音合成选通义千问云端**，不走本地 CosyVoice（手机跑不了）。CosyVoice 和本机 `say` 保留为可选，但不再投入。
- 这个决定的连带影响（已写进 `.scratch/mobile/spec.md`）：手机没有 macOS 的麦克风接口和 `say`，音频的采集和播放要搬到浏览器里，服务端要能在没有 macOS 的机器上运行。

## 已知风险

- 云端和 CosyVoice 的实际效果、延迟、情绪指令的写法，都需要用真实密钥/服务实测，目前只有假服务器的测试。
- CosyVoice 不同版本的指令格式可能不同；Qwen 的模型清单会变化。
- 云端合成每句话要多一次网络往返，延迟比本机高。
