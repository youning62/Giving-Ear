**What to build:** 打通 GivingEar 第一条端到端通路，范围如下：
- 建立项目骨架：Python 项目，Apache-2.0 协议，保留所依赖项目的版权声明
- 核心后台服务，包含：可替换的音频源接口及其 WAV 文件实现、语音活动检测、说话人识别器（sherpa-onnx + CAM++）、只存在于内存的临时档案、可替换的语音模型后端接口及其假后端、会话协调器、本地 WebSocket 事件流
- 命令行对话界面：连接事件流，滚动显示带说话人标签的对话记录

用 02 的测试语料运行时，终端依次显示"[说话人 1]"、"[说话人 2]"……；同一个人在本次会话里编号保持稳定；新出现的声音自动建立临时档案；假后端在说话人开口约 1 秒后收到对应的标签。陌生人阈值先用默认值，等 03 的结论出来后再调整。本票同时落地核心测试接口（WAV 音频源 + 假后端 + 断言事件流）的第一批测试，作为之后所有票的测试先例。参考规格：`.scratch/givingear-v1/spec.md`。

## 完成记录（2026-10-12）

**改动的阻塞关系：** 按用户决定，没有等 02 的真人语料，测试先改用 macOS 语音合成生成的三人对话（Eddy、Tingting、Sandy），由测试运行时自动生成。02 的语料到位后再补测。

**实现：**
- Python 包 `givingear`（uv 管理，Python 3.12），Apache-2.0 协议，第三方声明见 `NOTICE`。
- 模块：
  - 音频源（WAV 文件实现）
  - 语音活动检测（sherpa-onnx Silero VAD）
  - 说话人识别（3D-Speaker CAM++，本次会话的临时档案）
  - 事件总线
  - 本地 WebSocket 事件流（只监听本机 `127.0.0.1:8765`）
  - 语音模型后端接口及假后端
  - 会话协调器
  - 命令行
- 运行方式：`uv run givingear --wav 文件.wav [--realtime] [--port 0]`
- 模型首次使用时下载到 `~/.cache/givingear/models`，可以用 `GIVINGEAR_MODELS_DIR` 改位置。
- 陌生人阈值默认 0.45。依据是合成语音的初测：用完整一句话判断，同一个声音 ≥0.71、不同声音 ≤0.45；只用开口 1 秒判断，同一个声音 ≥0.56、不同声音 ≤0.40（Eddy 与 Reed 除外，两者声纹几乎相同）。这个阈值待 03 校准。
- 整句说完后，只有整句的声纹与初判的档案足够像，才用它充实档案，避免把别人的声音混进来。

**测试：** 共 8 个，都在核心测试接口上（WAV 输入 + 假后端）：
- 稳定且互不相同的编号
- 临时档案按顺序新建
- 开口后 1.5 秒内收到标签
- 标签名字前后一致
- 不向硬盘写入音频
- WebSocket 客户端能独立订阅事件流
- 命令行显示说话人标签
- 错误事件会出现在事件流中

**事件类型：**
- `status`（listening / stopped）
- `speech_start`
- `profile_created`
- `speaker_guess`（含 score、new）
- `speech_end`（含 start、full_score）
- `error`
- `closed`

所有事件都带 `wall_t`，和音频有关的事件还带 `audio_t`。
