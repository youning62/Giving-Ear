# 04: 验证：macOS 麦克风与系统回声消除

**What to build:** 一个最小验证脚本：证明 Python 程序在 macOS 上能取得麦克风权限，并开启系统自带的回声消除（语音处理模式）。用电脑扬声器播放一段语音，同时有人说话，检查录到的音频里播放的内容是否被基本消除、人声是否保留。还要确认：从终端启动时权限归属于哪个应用，第一次运行时会不会弹出授权窗口，以及没有权限时程序能检测到什么。结论写在本票末尾的"结论"小节，供 06、07、12 采用。参考规格：`.scratch/givingear-v1/spec.md`。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 能从 Python 程序打开麦克风，持续取得音频帧
- [ ] 开启系统回声消除后，扬声器播放的内容在录音中明显减弱（附播放前后对比录音或能量对比）
- [ ] 播放的同时，人声仍然清晰可辨
- [ ] 写明麦克风权限的授权方式，以及没有权限时可以检测到的具体表现
- [ ] 如果 Python 方案行不通，给出备选方案（例如用 Swift 写一个小程序负责采集音频）

## 结论（2026-10-12，MacBook Pro 内置麦克风 + 扬声器，macOS 26.6）

**麦克风权限：通过。**
- 从终端运行时，权限归属于"终端"应用。
- 第一次请求会弹出系统授权窗口，点"允许"后状态为 authorized。
- 程序可以检测到四种状态：notDetermined / restricted / denied / authorized，可用于 12 的出错提示。

**系统回声消除（AVAudioEngine 语音处理模式）：部分通过。**
- 坑：必须先初始化输出端和混音器，再开启语音处理，否则引擎启动失败（-10875）。
- 开启语音处理后，输入为 48 kHz、9 声道，各声道内容相同，取第一个声道即可。
- 经混音器转成单声道的读取方式录出来全是静音，不可用。
- 回声消除效果：扬声器播放、房间安静时，关闭为约 -23 dBFS，开启后适应几秒，稳定在约 -62 dBFS，压低约 40 dB。
- 没有播放时，人声保留良好（关闭约 -26 dBFS，开启约 -22 dBFS，有自动增益）。
- **失败项**：扬声器播放的同时有人说话，录音几乎是静音（约 -61 dBFS），人声被一并压掉。这样一来，AI 说话期间根本听不到用户，"开口即打断"无法实现。

**后续方向（暂缓，按用户决定先打通 AI 连接）：**
- 首选：改用 WebRTC 音频处理模块做回声消除（例如 LiveKit Python SDK 自带的音频处理模块），把 AI 播放的音频作为参考信号传入。这个方案需要验证。
- 备选：尝试关闭语音处理的自动增益或闪避设置，看看双方同时说话时的表现能否改善。
- 开发阶段：戴耳机，或关闭语音处理。
- 测试脚本和录音在 `spikes/04-mic-aec/`。
