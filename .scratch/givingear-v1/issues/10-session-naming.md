# 10: 口头命名（只在本次会话有效）

**What to build:** 陌生说话人在对话中自我介绍（如"我叫小王"）时，AI 调用"给当前说话人命名"工具，把当前的临时档案"说话人 N"改成真名。之后的说话人标签和对话记录都显示新名字，插入模型会话的标签也使用新名字，事件流发出"命名"事件。命名只在本次会话有效：程序关闭后不保留，也不会产生已注册档案。参考规格：`.scratch/givingear-v1/spec.md`。

**Blocked by:** 05（最小通路）

**Status:** done（2026-10-12）

- [x] 测试：假后端模拟命名工具调用后，同一个人后续的标签都变成新名字
- [x] 测试：假后端收到的说话人标签使用新名字
- [x] 测试：重启核心后，这个人重新被标为"说话人 N"，档案库里没有他
- [ ] （待 08）已注册的人被命名时，只改本次会话的显示名，不修改他的已注册档案

## 完成记录（2026-10-12）

- 新增与模型无关的工具定义模块，第一个工具是 `name_speaker(name, speaker?, aliases?)`。省略 `speaker` 时，指刚才说话的人；`speaker` 可以写"说话人 2"或"说话人2"。
- 后端接口新增"工具调用"事件和 `send_tool_result`。Gemini 后端把工具转成 function declarations，收到 tool_call 后由核心处理，再把结果返回。
- 命名后，事件流发出 `profile_renamed`（包含别名，为 14 做准备）；之后的说话人标签、本地转写都使用新名字。
- 系统提示加入"有人自我介绍时调用 name_speaker，并给出别名"的规则。
- 实机（合成语音 + 真 Gemini）：小王和 Jennifer 自我介绍后，AI 都主动调用了工具，标签随之更新。
- 最后一条"已注册的人被命名"要等 08 做完才能验证。
