# 手机上使用

**Status:** needs-triage（2026-11-05）：只是写下了问题，还没有设计，需要和用户一起定方案

## 背景

用户确认软件以后要在手机上登录使用（2026-11-05）。目前的程序是"一台 Mac 上的本地程序"：

- 麦克风和扬声器由 Python 进程直接用 macOS 的 AVAudioEngine 接管（`mac_audio.py`）；
- 本机声音用 macOS 的 `say`（`tts.py`）；
- 账号、声纹库、API 密钥都存在这台电脑的 `~/.givingear/`、`~/.config/givingear/`；
- 网页只是同一台电脑上的管理和查看界面，音频不经过浏览器。

手机上没有这些：音频必须在**手机的浏览器里**采集和播放，服务要能运行在**不是 macOS 的服务器**上。

## 需要和用户一起定的决策

1. **服务放在哪里？** 用户自己的电脑（手机通过局域网/内网穿透访问）还是云服务器？这决定了声纹、密钥存在哪、谁来保管。
2. **音频怎么传？** 浏览器采集麦克风（getUserMedia）→ WebSocket 把 16 kHz PCM 发给服务；AI 的语音由服务发回，浏览器播放。回声消除交给浏览器（`echoCancellation: true`）。
3. **手机浏览器的限制**：iOS Safari 要求用户点击后才能播放声音；需要 HTTPS 才能用麦克风（本机 `127.0.0.1` 除外）；后台会被暂停。
4. **本地模型放在服务器上**（VAD、声纹、转写）：服务器要有足够的 CPU；多用户同时用时的并发。
5. **隐私与合规**：声纹是生物特征数据，放到服务器上就不再是"只在你自己电脑里"，需要重新审视加密、存储、同意和删除。账号的 ADR 0001 是按"本机"写的。
6. **语音合成**：已决定用通义千问云端（手机没有 `say`）；每句话是一次网络往返，是否改成流式合成以降低延迟。
